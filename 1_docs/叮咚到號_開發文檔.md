# 叮咚到號 — 開發文檔

> 最後更新：2026-03-28

---

## 1. 專案簡介

叮咚到號是一個醫院看診叫號追蹤系統，透過 LINE Official Account 讓用戶即時查詢醫院看診進度，並在接近自己號碼時收到推播通知。

核心功能：
- 輸入醫院名稱查詢即時叫號進度
- 選擇科別 → 醫師 → 開始追蹤
- 自動每 15 秒檢查號碼變動，推播通知用戶
- 支援同時追蹤最多 3 位醫師
- 到號時自動通知並停止追蹤

│  │  (webhook 接收)      (快取+任務佇列)   │  │
│  │                                        │  │

│  │  (排程觸發)          (爬蟲+推播)       │  │
│  │                                        │  │
│  └────────────────────────────────────────┘  │

│     ▼                                        │

│                                              │

### 架構分工

| 元件 | 管理方式 | 角色 |
|------|---------|------|
| Nginx | aaPanel | SSL 終端、反向代理、靜態檔案 |
| MySQL | aaPanel | 用戶資料、追蹤任務、歷史紀錄（持久化） |
| FastAPI | Docker | LINE webhook 接收、對話狀態機、訊息回覆 |
| Celery Worker | Docker | 醫院爬蟲、號碼比對、LINE Push 推播 |
| Celery Beat | Docker | 定時排程（每 15 秒觸發爬蟲任務） |
| Redis | Docker | 任務佇列、叫號快取、對話狀態暫存 |

## 5. 兩個版本說明

### 測試版（目前階段）

用 `line_bot.py` + `demo_chat.py`，不需要 MySQL/Redis，用 SQLite + 記憶體內 mock 資料。目的是快速驗證 LINE 訊息收發和對話流程。

啟動方式：
```bash
docker compose up -d linebot    # 只啟動 linebot service
```

特點：
- 8 位虛擬醫師，每小時重新計號
- 號碼每 15 秒 ~ 3 分鐘隨機跳動
- server-side 追蹤用 threading + LINE push
- 不依賴外部資料庫或 Redis

### 正式版

用 `app/` 目錄下的完整架構，依賴 MySQL + Redis + Celery。

啟動方式：
```bash
docker compose up -d app worker beat redis    # 啟動正式版全套
```

特點：
- 真實爬蟲抓醫院網站
- Celery 背景排程，按醫院分組爬（不按用戶）
- Redis 快取叫號資料，用戶查詢秒回
- MySQL 持久化所有資料
- 可水平擴展 worker 數量

## 6. 部署步驟（aaPanel + Docker）

### 前置條件

- aaPanel 伺服器，已安裝 Docker + Docker Compose
- 域名 `dindon.cleanhome.tw` 已指向伺服器 IP
- aaPanel 已設定 SSL 憑證（Let's Encrypt）
- MySQL 資料庫 `ajz-dindon` 已建立

### 步驟一：上傳程式碼到伺服器

```bash
# 在伺服器上建立目錄
mkdir -p /www/wwwroot/dingdon
cd /www/wwwroot/dingdon

# 方法 A：git clone（推薦）
git clone <your-repo-url> medical-queue-notify
cd medical-queue-notify

# 方法 B：直接上傳
# 透過 aaPanel 檔案管理 或 scp 上傳整個 medical-queue-notify 資料夾
```

### 步驟二：設定環境變數

確認 `.env` 檔案內容：

```env
# LINE Official Account
LINE_CHANNEL_SECRET=你的channel_secret
LINE_CHANNEL_ACCESS_TOKEN=你的access_token

# MySQL（aaPanel 管理，Docker 內透過 host.docker.internal 連線）
MYSQL_HOST=host.docker.internal
MYSQL_PORT=3306
MYSQL_USER=ajz-dindon
MYSQL_PASSWORD=你的密碼
MYSQL_DATABASE=ajz-dindon

# Redis（Docker 內部）
REDIS_URL=redis://redis:6379/0

# 應用設定
APP_ENV=production
APP_DEBUG=false
SCRAPE_INTERVAL_SECONDS=15
NOTIFY_THRESHOLD=5
```

注意：`MYSQL_HOST` 在 Docker 內要用 `host.docker.internal` 來連到 aaPanel 上的 MySQL，不能用 `localhost`（那會指向 container 自己）。

### 步驟三：啟動測試版 LINE Bot

```bash
cd /www/wwwroot/dingdon/medical-queue-notify

# 建置並啟動（只啟動 linebot 測試版）
docker compose up -d linebot

# 確認狀態
docker compose ps
docker compose logs linebot

# 測試健康檢查
curl http://localhost:5000/health
# 預期回應：{"status":"ok","active_trackings":0}
```

### 步驟四：設定 Nginx 反向代理

在 aaPanel 中：

1. 進入 Website → `dindon.cleanhome.tw` → Configuration（或 設定）
2. 在 Nginx 設定中加入以下內容（貼在 server 區塊內）：

```nginx
# LINE Bot 測試版（port 5000）
# 測試完成後改 port 8000 切到正式版
location /webhook {
    proxy_pass http://127.0.0.1:5000/webhook;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 60s;
}

location /health {
    proxy_pass http://127.0.0.1:5000/health;
    proxy_set_header Host $host;
}
```

3. 儲存並重啟 Nginx

### 步驟五：設定 LINE Developers Console

1. 前往 [LINE Developers Console](https://developers.line.biz/)
2. 選擇你的 Provider → 選擇 Messaging API channel
3. 在 Messaging API 頁籤：
   - Webhook URL 設為：`https://dindon.cleanhome.tw/webhook`
   - 點擊 Verify → 應回傳 Success
   - 開啟 Use webhook：ON
4. 在同一頁確認 Auto-reply messages：OFF（不要用 LINE 內建自動回覆）

### 步驟六：測試

1. 用手機 LINE 加入你的 LINE Official Account
2. 輸入「測試」→ 應回傳科別列表
3. 選擇科別 → 選醫師 → 追蹤 → 輸入號碼
4. 等待 15 秒，應收到號碼更新推播

### 步驟七：切換到正式版（測試完成後）

```bash
# 啟動正式版全套服務
docker compose up -d app worker beat redis

# 修改 nginx.conf 把 port 5000 改為 8000
# 在 aaPanel 重啟 Nginx

# 停止測試版
docker compose stop linebot
```

## 7. 對話狀態機

```
                輸入醫院名稱
    ┌──────┐ ─────────────→ ┌────────────┐
    │ idle │                 │ choose_dept│
    └──────┘ ←───────────── └────────────┘
        ↑     9=返回主選單        │ 選科別
        │                        ▼
        │                  ┌──────────────┐
        │  9=返回主選單    │choose_doctor │
        │ ←─────────────── └──────────────┘
        │                        │ 選醫師
        │                        ▼
        │                  ┌──────────────┐
        │  9=返回主選單    │ after_result │
        │ ←─────────────── └──────────────┘
        │                        │ 1=追蹤
        │                        ▼
        │                  ┌──────────────┐
        │  取消追蹤        │  tracking    │（server-side）
        │ ←─────────────── └──────────────┘
        │                        │ 到號
        └────────────────────────┘ 自動停止
```

導航鍵規則：
- choose_dept：`9` = 返回主選單（無 `0`）
- choose_doctor：`0` = 返回科別列表，`9` = 返回主選單
- after_result：`1` = 追蹤，`2` = 換醫師，`0` = 換科別，`9` = 返回主選單

## 8. 追蹤引擎

### 測試版（line_bot.py）

使用 Python threading，每 15 秒 poll mock 資料：

```python
_tracking_store: dict[str, list[dict]] = {}   # user_id → [track_obj, ...]
_waiting_number: dict[str, dict] = {}          # user_id → 等待輸入號碼的 track

# 背景執行緒
threading.Thread(target=_poll_worker, daemon=True)
```

### 正式版（app/tasks/ + app/services/）

使用 Celery 排程，按醫院分組爬蟲，差異推播：

```
Celery Beat 每 15 秒
  → scrape.py：按醫院爬蟲 → 結果存 Redis
  → notify.py：比對所有追蹤任務 → 有變動才推播
```

核心差異：測試版是「每個追蹤各自 poll」，正式版是「按醫院批次爬 + 差異推播」。

## 9. 醫院爬蟲 Adapter

爬蟲採用 Adapter Pattern（`app/scrapers/`），每間醫院一個 adapter，統一介面：

```python
# app/scrapers/base.py
class BaseAdapter:
    hospital_code: str
    hospital_name: str

    async def scrape(self) -> list[ClinicProgress]:
        """爬取即時看診進度"""
        raise NotImplementedError
```

## 14. 伺服器配置建議

日活 10,000 人的配置：

| 項目 | 建議 |
|------|------|
| CPU | 4 核 |
| RAM | 8 GB |
| 硬碟 | 80 GB SSD |
| 頻寬 | 10 Mbps |
| 月費估算 | NT$1,500 ~ 2,000 |

資源分配估算：
- Nginx：~50 MB
- Docker Engine：~200 MB
- FastAPI (2 workers)：~300 MB
- Celery Worker × 2：~400 MB
- Celery Beat：~100 MB
- Redis：~256 MB（maxmemory 設定）
- MySQL：~500 MB
- 系統 + 緩衝：~1-2 GB
- 合計約 2-3 GB，8 GB 有充足餘裕

## 16. 疑難排解

### Docker 內無法連到 MySQL

原因：Docker container 裡的 `localhost` 指向 container 自己，不是宿主機。

解法：`.env` 裡 `MYSQL_HOST` 設為 `host.docker.internal`，docker-compose 加 `extra_hosts`：
```yaml
extra_hosts:
  - "host.docker.internal:host-gateway"
```

### LINE webhook 回 400 Invalid signature

原因：`LINE_CHANNEL_SECRET` 不對，或 Nginx 轉發時改了 request body。

檢查：
1. 確認 .env 裡的 secret 跟 LINE Console 一致
2. Nginx 不要加 `proxy_set_header Content-Type`（讓原始 header 通過）

### LINE 訊息送出但沒收到回覆

檢查順序：
1. `docker compose logs linebot` 看有沒有收到 webhook
2. 確認 Nginx 有正確轉發（`curl -X POST https://dindon.cleanhome.tw/webhook`）
3. 確認 LINE Console 的 webhook URL 正確且 Verify 成功
4. 確認 Use webhook = ON、Auto-reply = OFF

### Push 推播失敗

原因：LINE Messaging API 的免費方案每月有推播上限（目前 500 則/月）。超過需升級為 Light Plan 或 Standard Plan。

解法：在 [LINE Official Account Manager](https://manager.line.biz/) 確認方案和用量。
