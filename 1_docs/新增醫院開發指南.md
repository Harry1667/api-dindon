## 1. 系統架構概覽

```
┌──────────────┐     ┌───────────────────┐     ┌──────────┐
│  醫院網站 /   │────▶│  Scraper Adapter   │────▶│  MySQL   │

└──────────────┘     └───────────────────┘     └────┬─────┘
                                                     │
                     ┌───────────────────┐           │
                     │  FastAPI Backend   │◀──────────┘
                     │  /api/progress/*   │
                     └────────┬──────────┘
                              │
                     ┌────────▼──────────┐
                     │  LINE Messaging    │
                     │  API (通知推播)     │
```

每家醫院有一個 **Adapter**，負責從醫院網站或政府開放資料 API 抓取看診進度，解析後統一輸出為 `ClinicProgressData` 標準格式，存入 MySQL 並快取到 Redis。

## 2. 核心資料結構

### ClinicProgressData（標準輸出格式）

所有 Adapter 的 `fetch_all_progress()` 必須回傳 `list[ClinicProgressData]`：

```python
@dataclass
class ClinicProgressData:
    hospital_code: str        # 醫院代碼，如 "wanfang"
    hospital_name: str        # 醫院名稱，如 "萬芳醫院"
    date: str                 # 看診日期，格式 "YYYY/MM/DD"
    session: str              # 診別："上午診" / "下午診" / "夜診"
    department: str           # 科別，如 "精神科"
    doctor_name: str          # 醫師姓名，如 "許元彰"
    clinic_room: str          # 診間號碼，如 "282診"
    current_number: int       # 目前看診號碼
    next_number: int          # 下一位號碼
    is_current_skipped: bool  # 目前號碼是否過號
    is_next_skipped: bool     # 下一號碼是否過號
    fetched_at: datetime      # 抓取時間（台灣時區）
```

### hospitals 資料表

| 欄位             | 類型          | 說明                         |
|------------------|--------------|------------------------------|
| `id`             | INT PK       | 自動遞增                      |
| `code`           | VARCHAR(50)  | 醫院代碼（唯一），如 `wanfang`  |
| `name`           | VARCHAR(100) | 醫院名稱                      |
| `url`            | TEXT         | 看診進度查詢網址                |
| `adapter_name`   | VARCHAR(100) | 爬蟲 Adapter 類別名稱          |
| `is_active`      | BOOLEAN      | 是否啟用（預設 true）           |
| `scrape_interval`| INT          | 爬蟲間隔（秒），預設 60         |
| `created_at`     | DATETIME     | 建立時間                      |
| `updated_at`     | DATETIME     | 更新時間                      |

## 3. 新增醫院的完整步驟

以下是新增一家醫院需要修改的所有檔案，共 4 步：

### Step 1：建立 Adapter 檔案

在 `app/scrapers/` 下新增 Python 檔案，繼承 `BaseHospitalAdapter`：

```python
# app/scrapers/example_hospital.py

from app.scrapers.base import BaseHospitalAdapter
from app.schemas.clinic import ClinicProgressData

class ExampleHospitalAdapter(BaseHospitalAdapter):
    hospital_code = "example"          # 唯一代碼（kebab-case）
    hospital_name = "範例醫院"
    base_url = "https://example.com/progress"

    async def fetch_all_progress(self) -> list[ClinicProgressData]:
        # 實作抓取邏輯，詳見第 4 節
        ...

    async def get_departments(self) -> list[str]:
        # 回傳該醫院所有科別名稱
        ...
```

### Step 2：註冊到 AdapterRegistry

編輯 `app/scrapers/registry.py`，加入 import 和註冊：

```python
# --- 新增 import ---
from app.scrapers.example_hospital import ExampleHospitalAdapter

# --- 在適當區域註冊 ---
AdapterRegistry.register(ExampleHospitalAdapter())  # 範例醫院
```

### Step 3：新增 Seed 資料

編輯 `app/main.py` 中的 `_seed_hospitals()` 函式，在 `seeds` 陣列中新增：

```python
{"code": "example", "name": "範例醫院",
 "url": "https://example.com/progress",
 "adapter_name": "ExampleHospitalAdapter", "scrape_interval": 60},
```

### Step 4：新增別名

在 `app/main.py` 的 `_seed_hospital_aliases()` 和 `scripts/seed_aliases.py` 中新增：

```python
"example": ["範例", "example"],
```

別名讓使用者可以用「範例」或「example」在 LINE 上搜尋到這家醫院。

### 完成後驗證

啟動服務後，透過 API 確認：

```bash
# 確認醫院已註冊
curl http://localhost:8000/api/hospitals

# 即時測試爬蟲（直接呼叫 Adapter，不經快取）
curl http://localhost:8000/api/progress/example
```

## 4. 爬蟲 Adapter 開發詳解

### 基底類別

```python
class BaseHospitalAdapter(ABC):
    hospital_code: str = ""   # 醫院唯一代碼
    hospital_name: str = ""   # 醫院顯示名稱
    base_url: str = ""        # 資料來源網址

    @abstractmethod
    async def fetch_all_progress(self) -> list[ClinicProgressData]:
        """抓取該醫院所有目前看診中的診間進度"""
        ...

    @abstractmethod
    async def get_departments(self) -> list[str]:
        """取得該醫院所有科別名稱"""
        ...
```

你只需要實作這兩個方法。

### fetch_all_progress() 實作重點

1. **使用 httpx 非同步請求**：所有 HTTP 請求統一使用 `httpx.AsyncClient`，timeout 設為 15 秒
2. **錯誤處理**：捕獲 `httpx.HTTPError`，log 錯誤後回傳空 list（不要讓單一醫院錯誤影響整體）
3. **時區**：所有時間使用台灣時區 `timezone(timedelta(hours=8))`
4. **session 標準化**：統一為 `"上午診"` / `"下午診"` / `"夜診"` 三種
5. **過號處理**：如果來源有過號資訊，要正確設定 `is_current_skipped` / `is_next_skipped`
6. **跳過無效資料**：`current_number == 0 and next_number == 0` 的紀錄應跳過


## 5. 三種資料來源模式

目前已接入的醫院可分為三種技術模式，開發前請先確認目標醫院屬於哪種：

### 模式 A：HTML 網頁爬蟲

直接 GET/POST 醫院網頁，用 BeautifulSoup 解析 HTML。

**適用場景**：醫院有公開的看診進度網頁，資料直接嵌在 HTML 中。

**範例醫院**：萬芳醫院（GET）、長庚醫院（POST form）、台北榮總

**關鍵技術**：
- `httpx` 發送請求
- `BeautifulSoup` + `lxml` 解析 HTML
- `re` 正規表達式提取號碼
- 注意 ASP.NET ViewState、CSRF token 等反爬機制

```python
# 萬芳醫院：純 GET，解析 .card-panel 元素
resp = await client.get(self.base_url)
soup = BeautifulSoup(resp.text, "lxml")
cards = soup.select(".card-panel")

# 長庚醫院：POST form，帶科別+時段參數
resp = await client.post(url, data={"dept": "02", "time": "1"})
soup = BeautifulSoup(resp.text, "html.parser")
rows = soup.find("table").find_all("tr")
```

### 模式 B：AJAX / POST API

醫院網頁透過 AJAX 載入資料，需模擬 XHR 請求。

**適用場景**：醫院網頁用 JavaScript 動態載入資料。

**範例醫院**：台大醫院（POST AJAX 取得 HTML fragment）

**關鍵技術**：
- 需帶 `X-Requested-With: XMLHttpRequest` header
- 需帶 `Referer` header
- 通常需遍歷科別+時段代碼組合

```python
resp = await client.post(
    self.base_url,
    data={"vHospCode": "T0", "DropDownDept": "MED", "DropDownAMPM": "1"},
    headers={
        "X-Requested-With": "XMLHttpRequest",
        "Referer": "https://reg.ntuh.gov.tw/...",
    },
)
```

**效能提示**：根據當前時間只查詢相關時段，減少不必要的請求：
```python
hour = now.hour
if hour < 12:
    active_times = ["1"]        # 只查上午
elif hour < 17:
    active_times = ["1", "2"]   # 查上午+下午
else:
    active_times = ["2", "3"]   # 查下午+夜診
```

### 模式 C：政府開放資料 JSON API

直接呼叫政府開放資料平台 API，回傳 JSON。

**適用場景**：醫院資料已由地方政府整合上開放資料平台。

**範例醫院**：新北聯合醫院（data.ntpc.gov.tw）、高雄聯合醫院（api.kcg.gov.tw）

**優點**：結構化 JSON、不怕網頁改版、通常有 API 文件

**注意事項**：
- 檢查 API 回傳的 success/RtnCode 欄位
- 非看診時段 API 可能回傳空資料或錯誤碼（不是 bug）
- `next_number` API 通常不提供，用 `current_number + 1` 估算
- `is_current_skipped` / `is_next_skipped` 通常無法取得，設為 `False`

```python
resp = await client.get(api_url, headers={"Accept": "application/json"})
payload = resp.json()

# 高雄市 API 需檢查 RtnCode
if payload.get("data", {}).get("RtnCode") != "0":
    return []  # HIS 系統未回應

records = payload["data"]["ProcessInfo"]
```

### 多院區共用 Adapter 的設計模式

長庚、台大、馬偕、新北聯醫等體系採用「一個 Adapter 類別 + 建構子參數區分院區」的方式：

```python
# 長庚醫院：用 branch_id 區分院區
class ChangGungAdapter(BaseHospitalAdapter):
    def __init__(self, hospital_code, hospital_name, branch_id):
        self.hospital_code = hospital_code
        self.hospital_name = hospital_name
        self.branch_id = branch_id
        self.base_url = f"https://register.cgmh.org.tw/Progress/{branch_id}"

# 建立各院區實例
taipei_changgung = ChangGungAdapter("changgung-taipei", "台北長庚", "1")
linkou_changgung = ChangGungAdapter("changgung-linkou", "林口長庚", "3")
kaohsiung_changgung = ChangGungAdapter("changgung-kaohsiung", "高雄長庚", "8")
```

新增同體系的院區時，只需建立新的實例並註冊即可，不需要寫新的 Adapter。

長庚可用的院區代碼：`1`=台北, `3`=林口, `5`=桃園, `6`=基隆, `8`=高雄, `9`=嘉義, `A`=鳳山, `C`=雲林, `D`=土城

## 7. 開發注意事項與常見問題

### Checklist（新增醫院前確認）

- [ ] 確認醫院有公開的看診進度頁面或 API
- [ ] 確認資料來源在看診時段外的行為（回空？報錯？）
- [ ] 確認是否需要特殊 headers（Referer、Cookie、CSRF token）
- [ ] 確認是否有反爬機制（rate limit、IP 封鎖、CAPTCHA）
- [ ] 決定 `hospital_code`（全小寫 kebab-case，如 `my-hospital`）
- [ ] 決定 `scrape_interval`（一般網頁 60s，API 可以 300s）

### 常見問題

**Q: 抓取的時候回傳空資料？**
非看診時段（如深夜、假日），很多醫院的網頁本身就沒有資料。請在實際看診時段測試。

**Q: 多院區醫院怎麼處理？**
如果院區共用同一套網站系統（只差 URL 參數），建立一個 Adapter 類別，用建構子參數區分。參考 `ChangGungAdapter` 或 `NewTaipeiUnitedAdapter`。

**Q: 醫院網頁改版了怎麼辦？**
HTML 爬蟲最容易受影響。改版後只需修改對應 Adapter 的 `_parse_html()` 或 `_parse()` 方法，不影響其他醫院。

**Q: session（診別）有幾種值？**
統一為三種：`"上午診"`、`"下午診"`、`"夜診"`。不同醫院可能用不同名稱（早診、午診、晚診等），請在解析時統一轉換。

**Q: next_number 來源沒有提供？**
如果 API 沒有提供下一號，用 `current_number + 1` 估算。參考 `KaohsiungUnitedAdapter` 和 `NewTaipeiUnitedAdapter` 的做法。

**Q: 過號資訊來源沒有提供？**
設為 `False` 即可。只有部分醫院（如萬芳、長庚）的頁面會顯示過號狀態。
