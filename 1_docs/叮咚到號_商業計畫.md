# 叮咚到號 — 商業計畫書

> 內部規劃文件 ｜ 2026.03

---

## 一、產品定位

叮咚到號是一款透過 LINE 通知的醫療看診即時叫號追蹤服務。使用者輸入醫院與醫師名稱，即可獲得目前看診進度，並在號碼變動時收到推播通知，解決「不知道還要等多久、怕錯過叫號」的痛點。

核心價值：讓病患離開候診區也不漏號，把等待時間還給自己。

---

## 二、目標用戶

| 用戶類型 | 場景 | 痛點 |
|---------|------|------|
| 門診病患 | 掛號後需等 1～3 小時 | 不敢離開候診區，怕過號 |
| 陪同家屬 | 帶長輩/小孩看診 | 需要來回確認看診進度 |
| 多科看診者 | 同天掛 2～3 科 | 無法同時守在不同診間 |
| 上班族 | 早上掛號、中午看診 | 無法一直盯著醫院 app |

## 三、功能分級與定價

### 免費版（基礎版）

| 功能 | 說明 |
|------|------|
| 查詢看診進度 | 不限次數，輸入醫院名/別名即可查詢 |
| 同時追蹤 1 位醫師 | 即時叫號追蹤，號碼變動推播通知 |
| 輸入掛號號碼 | 顯示「還剩 N 號」或「已過號」 |
| 到號自動通知 | 輪到時推播「已叫號！」並自動停止 |
| 查詢歷史 + 常用排序 | 記住你常看的醫院、科別、醫師 |
| 醫院別名查詢 | 輸入「三總」=「三軍總醫院」 |

### 付費版 — 叮咚 PRO（NT$49/月）

| 功能 | 說明 |
|------|------|
| 同時追蹤最多 3 位醫師 | 多科看診、幫家人同時追蹤 |
| 提前 N 號提醒 | 設定「還剩 5 號時提醒我」，抓出門時間 |
| 預估等候時間 | 根據歷史叫號速度，計算「大約還要等 N 分鐘」 |
| 更快的追蹤頻率 | 每 5 秒檢查一次（免費版 15 秒） |
| 看診紀錄 | 歷史看診查詢：哪天看了哪位醫師、等了多久 |
| 我的醫師清單 | 收藏常看醫師，一鍵查詢 + 追蹤 |
| 靜音時段 | 開會時暫停通知，結束後自動恢復 |
| 無廣告 | 移除所有廣告訊息 |

### 付費版 — 叮咚家庭方案（NT$79/月）

| 功能 | 說明 |
|------|------|
| 包含 PRO 所有功能 | — |
| 最多 5 位家庭成員 | 共用一個付費帳號 |
| 同時追蹤最多 5 位醫師 | 全家多科看診場景 |
| 長輩模式 | 大字體、語音播報叫號 |
| 代掛追蹤 | 幫家人掛號後直接開始追蹤，到號通知家人 |

## 四、更多付費可能 — 營收擴展

### 4.1 B2C 加值服務

| 項目 | 模式 | 預估定價 |
|------|------|---------|
| 單次追蹤包 | 不想月繳，一次買 5 次追蹤額度 | NT$29 / 5 次 |

| VIP 優先通道 | 伺服器優先處理，保證通知延遲 < 3 秒 | NT$99/月 |

### 4.2 B2B 醫療院所合作

| 項目 | 模式 | 預估定價 |
|------|------|---------|
| 醫院品牌專頁 | 醫院在叮咚到號內有專屬頁面，展示門診時刻表 | NT$3,000～10,000/月 |

| 門診資料 API | 提供即時叫號資料 API 給醫院自有 APP | 按呼叫量計費 |

### 4.3 B2B 廣告與導流

| 項目 | 模式 | 預估定價 |
|------|------|---------|

| 醫療保險合作 | 看診紀錄整合保險理賠快速通道 | 分潤 |

### 4.4 資料加值服務

| 項目 | 模式 | 說明 |
|------|------|------|

## 五、技術架構概要

```
用戶 (LINE) ←→ LINE Messaging API ←→ Flask 後端 ←→ 醫院爬蟲/API
                                         ↓
                                   MySQL (用戶資料/別名/歷史)
                                         ↓
                                   排程追蹤引擎 (polling)
```

目前已完成：長庚（台北/林口/高雄）、新北聯合（板橋/三重）、測試醫院（模擬資料）

規劃中：萬芳、台大、台北榮總、馬偕、國泰、新光、三軍總醫院

## 八、損益估算

| 指標 | 數值 |
|------|------|
| 月營運成本 | ~NT$4,000 |
| PRO 方案月費 | NT$49 |
| 損益平衡用戶數 | ~82 位付費用戶 |
| 目標轉換率 | 免費→付費 5% |
| 損益平衡總用戶數 | ~1,640 位 |

以台灣每月門診人次約 2,700 萬次、智慧型手機普及率 > 90% 來看，1,640 位用戶是可實現的目標。

## 九、競爭分析

| 競品 | 優勢 | 劣勢 |
|------|------|------|
| 各醫院官方 APP | 資料最即時 | 每家獨立、UI 差、不跨院 |
| 醫院網頁進度查詢 | 免安裝 | 需手動刷新、無通知 |
| 叮咚到號 | LINE 免裝、跨院、到號主動通知、多追蹤 | 需爬蟲維護、資料非即時同步 |

核心競爭力：用戶不需安裝新 APP，在 LINE 中即可完成所有操作。

## 十、風險與對策

| 風險 | 對策 |
|------|------|
| 醫院網站改版導致爬蟲失效 | 監控 + 告警機制，快速修復；長期推動 API 合作 |
| 法規（個資法 / 醫療資料） | 僅爬取公開資料，不儲存病患醫療紀錄 |
| 醫院封鎖爬蟲 IP | 分散 IP、降低頻率；優先洽談正式 API 合作 |
| LINE 政策變動 | 備案：Telegram Bot / 獨立 APP |
| 付費轉換率低 | 先以免費版衝用戶量，透過數據驗證付費意願再調整 |
