# 叮咚到號 — 頁面處理邏輯

> 內部開發文件 ｜ 2026.03

---

## 系統架構

```
前端 (JavaScript, LINE 模擬 UI)
  ├── 訊息發送 sendMessage()
  ├── 追蹤引擎 (startTracking / pollForTrack / stopTracking)
  └── 前端攔截（追蹤指令、診號輸入、數字保護）
        │
        ▼
後端 (Python Flask)
  ├── /api/chat          → handle_message() 對話狀態機
  ├── /api/find_doctor   → 追蹤啟動時查找醫師
  └── /api/poll          → 追蹤中定期輪詢號碼
```

## 後端對話狀態機

後端維護每位用戶的對話狀態 `conv["state"]`，共 4 個狀態：

```
                    ┌──────────────────────────────────┐
                    │            idle                   │
                    │  （等待用戶輸入醫院名稱）          │
                    └──────┬────────────────────────────┘
                           │ 輸入醫院名 → 解析成功
                           │ → 抓取看診資料
                           ▼
                  ┌─ 只有1個科別 ─→ 直接顯示 ─→ after_result
                  │
           ┌──────┴──────────────────────┐
           │        choose_dept          │
           │   （選擇科別）               │
           │   1~N=選科  9=主選單         │
           └──────┬──────────────────────┘
                  │ 選到科別
                  ▼
           ┌─ 只有1位醫師 ─→ 直接顯示 ─→ after_result
           │
           ├──────────────────────────────┐
           │       choose_doctor          │
           │  （選擇醫師）                 │
           │  1~N=選醫師 0=回科別 9=主選單 │
           └──────┬───────────────────────┘
                  │ 選到醫師
                  ▼
           ┌──────────────────────────────┐
           │       after_result           │
           │  （看完結果，選下一步）        │
           │  1=追蹤 2=查詢別科 3=主選單   │
           └──────────────────────────────┘
                  │
         ┌────────┼────────┐
         ▼        ▼        ▼
      __TRACK__ choose_  reset→idle
      (前端追蹤)  dept
```

## 各狀態詳細說明

### idle（初始狀態）

觸發條件：首次進入 / 重置後 / 追蹤開始後

用戶輸入 → 處理流程：

| 輸入 | 行為 |
|------|------|
| 醫院名稱（萬芳、三總、台北長庚...） | `_resolve_hospital()` 解析 → 抓取資料 → 進入 choose_dept 或直接 after_result |
| 醫院名 + 科別（台北長庚 中醫內兒科） | 解析後帶 `extra_filter` 直接篩選顯示 → after_result |
| 「醫院」/「列表」 | 顯示支援醫院列表 |
| 「重置」/「取消」/「返回」 | 回到主選單（全域指令） |
| 其他文字 | 顯示歡迎訊息 + 使用說明 |

醫院解析優先序（`_resolve_hospital`）：
1. 測試醫院：`msg` 包含「測試」或「test」
2. 別名匹配：`HOSPITAL_ALIASES` 按別名長度降序掃描（防止「台大」搶走「台大兒童」）

解析結果分三種：
- 已支援 + 有資料 → 進入科別/醫師選擇流程
- 已支援 + 無資料 → `「目前醫師休息中，請在看診時間再查詢」`
- 尚未支援（code 以 `unsupported:` 開頭） → `「此醫院尚未開放查詢」`

---

### choose_dept（選科別）

顯示格式：
```
🏥 測試醫院
⏰ 03/28 22:34　共 7 個診間、5 個科別

請問您想看哪科？

  1. 內科（2位醫師） ⭐
  2. 中醫內科（2位醫師） ⭐
  3. 兒科（1位醫師）
  ...

💡 輸入數字或科別名稱
💡 輸入 9 返回主選單
```

科別排序邏輯：依用戶歷史查詢次數降序排列，有歷史的標記 ⭐

| 輸入 | 行為 |
|------|------|
| `1`~`N`（數字） | 選擇對應科別 |
| 科別名稱文字 | 完全匹配 → 子字串匹配（長度降序，防「內科」搶「中醫內科」） |
| `9` | 返回主選單 |
| 醫院名稱 | 重新解析為新查詢（遞迴 handle_message） |
| 「重置」/「取消」/「返回」 | 回到主選單（全域指令） |

選到科別後：
- 該科只有 1 位醫師 → 直接顯示結果 → after_result
- 該科多位醫師 → 進入 choose_doctor

---

### choose_doctor（選醫師）

顯示格式：
```
🏥 測試醫院 — 內科
共 2 位醫師，請選擇：

  1. 王大明 ⭐
  2. 李小華

💡 輸入數字或醫師名
💡 輸入 0 返回科別
💡 輸入 9 返回主選單
```

醫師排序邏輯：依用戶歷史查詢次數降序排列，有歷史的標記 ⭐

| 輸入 | 行為 |
|------|------|
| `1`~`N`（數字） | 選擇對應醫師 |
| 醫師名文字 | 完全匹配 → 子字串匹配（長度降序） |
| `0` | 返回科別列表（choose_dept） |
| `9` | 返回主選單 |
| 醫院名稱 | 重新解析為新查詢 |

選到醫師後 → 顯示看診進度結果 → after_result

---

### after_result（結果操作選單）

顯示格式：
```
🏥 測試醫院 看診進度
⏰ 03/28 22:34　共 1 個診間

📌 內科
  王大明 [診間101] 下午診 👉 13號 → 14號

接下來要做什麼？

  1. 🔔 追蹤 王大明
  2. 🔄 查詢別科（測試醫院）
  3. 🏠 返回主選單
```

| 輸入 | 行為 |
|------|------|
| `1` / 「追蹤」 | 回傳 `__TRACK__醫院\t科別\t醫師` → 前端啟動追蹤 → 後端 reset 為 idle |
| `2` / 「別科」 | 重新顯示科別列表 → choose_dept |
| `3` / 「返回」 | 回到主選單 → idle |
| 醫院名稱 | 重新解析為新查詢 |

## 前端處理邏輯

### 訊息處理優先序（sendMessage）

前端 `sendMessage()` 在送到後端之前，按以下順序攔截：

```
1. 等待診號輸入？（waitingForNumber）
   ├── 「跳過」/「略過」 → 不設定診號，繼續追蹤
   ├── 正整數 → 設定 userNumber
   │    ├── 已過號（curN >= num） → 顯示已過號，繼續追蹤
   │    └── 未到號 → 顯示「還剩 N 號」
   └── 其他 → 提示重新輸入
        （「取消」/「停止」/「狀態」穿透到下一層）

2. 「取消全部追蹤」/「停止全部追蹤」
   → stopAllTracking()

3. 「取消追蹤」/「停止追蹤」
   ├── 只有1個追蹤 → 直接停止
   ├── 帶醫師名（取消追蹤 王大明） → 停止指定的
   └── 多個追蹤未指定 → 列出追蹤清單，請用戶指定

4. 「狀態」/「追蹤狀態」
   → 顯示所有追蹤中醫師的即時進度

5. 「追蹤 醫院 科別 醫師」（直接追蹤指令）
   → 解析 → startTracking()

6. 追蹤中 + 輸入 0 + 不在選擇流程（!inBackendFlow）
   → 送醫院名到後端 → 顯示科別列表
   → 設定 inBackendFlow = true

7. 追蹤中 + 純數字 + 不在選擇流程
   → 攔截，顯示提示（避免誤觸後端）

8. 送到後端 /api/chat
   → 收到回覆：
      ├── __TRACK__ 開頭 → 解析 → startTracking()
      │    → inBackendFlow = false
      └── 一般回覆 → 顯示
           → 含「哪科」/「請選擇」/「接下來要做什麼」
              → inBackendFlow = true（仍在選擇流程）
           → 其他 → inBackendFlow = false
```

### 追蹤引擎

#### startTracking(hospitalName, branchId, deptFilter, doctorFilter)

```
1. 檢查重複追蹤 → 已追蹤同一醫師則跳過
2. 檢查上限 → 超過 MAX_TRACKS(3) 則提示
3. 呼叫 /api/find_doctor 取得目前號碼
4. 建立新 tracking 物件 → push 到 trackings[]
5. 顯示初始號碼 + 「已開始追蹤」
6. 顯示「請問您的掛號號碼是幾號？」
7. 顯示追蹤提示（還可追蹤 N 位 / 輸入 0 查科別）
8. 啟動 setInterval → 每 15 秒 pollForTrack(t)
```

#### pollForTrack(t)

```
每 15 秒執行一次：

1. 呼叫 /api/poll 取得最新號碼
2. 若找不到醫師（休診） → 自動停止
3. 號碼有變動時：
   ├── 目前叫號 = 用戶號碼 且 未過號
   │    → 「輪到您了！已叫號！」 → 自動停止追蹤
   └── 其他變動
        → 顯示「號碼更新」+ 用戶狀態（還剩N號 / 已過號）
4. 更新標題列
```

#### 到號判斷邏輯

```
自動停止條件（唯一）：
  curN === userNumber && !curSkip && !notifiedArrival

不停止的情況：
  curN > userNumber        → 已過號，持續追蹤（醫師可能回叫）
  curN === userNumber 但過號 → 顯示過號，繼續追蹤
  用戶未設定號碼           → 持續追蹤直到看診結束
```

---

### 用戶狀態顯示（formatUserStatus）

| 情況 | 顯示 |
|------|------|
| 未設定號碼 | 不顯示 |
| `curN > userNumber` | `您是 N號，已過號，持續追蹤中` |
| `curN === userNumber` | `您的號碼 N號，正在叫號` |
| `curN < userNumber` | `您是 N號，還剩約 X 號` |

## 資料流

### 查詢流程

```
用戶輸入「台北長庚」
  → _resolve_hospital() 別名匹配 → code="1", label="台北長庚"
  → _fetch_results("1", "台北長庚")
     → fetch_changgung(branch_id="1") 爬蟲抓取
  → 回傳 results[]
  → 依科別分組 → choose_dept
```

### 追蹤流程

```
後端回傳 __TRACK__台北長庚\t中醫內兒科\t游汶霖
  → 前端攔截解析
  → startTracking("台北長庚", "1", "中醫內兒科", "游汶霖")
  → /api/find_doctor → 找到 dept_code, time_code
  → setInterval 每 15 秒呼叫 /api/poll
  → 號碼變動 → addBotMsg 通知
  → 到號 → stopTracking
```

### 歷史記錄流程

```
每次查詢/選擇都記錄：
  record_history(user_id, hospital_code)                    ← 查詢醫院
  record_history(user_id, hospital_code, department)         ← 選擇科別
  record_history(user_id, hospital_code, department, doctor) ← 選擇醫師

排序時讀取：
  get_history_counts(user_id, hospital_code, field)
  sort_by_history(items, history_counts) → 依次數降序，有歷史的排前面 + ⭐
```

| 端點 | 方法 | 用途 | 參數 |
